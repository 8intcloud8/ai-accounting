AI Accounting code map

A set of Codex plugins that take a business from bank statements and invoices to a reviewed Australian BAS draft. Everything runs on the user's computer; the accounting records live in one SQLite database per business.

  • 17 plugins, one skill each
  • Python 3.11 core, standard library
  • 2 Node MCP servers for Gmail
  • Money in integer cents
  • Never lodges with the ATO

The layers

The user talks to Codex. Codex follows a skill's instructions and runs that skill's scripts. Every script that touches the books goes through the shared core, which reads and writes the workspace.

User
Asks in a Codex chat, e.g. “prepare my BAS for July to September”. Answers questions and approves proposals.

The BAS run, step by step

The workflow has seven steps. Each problem the database reports belongs to one step and one owning skill. Steps marked user stop for an answer or approval.

1

Setup

setup-accountinggrill-me-taxuser

Checks the computer (Python, packages, Node), creates the workspace, saves the business profile (entity, GST registration and basis) and the BAS method. Asks once whether to turn on the review-page buttons.

2

Bank statements

extract-bankstatements

Reads CSV, Excel or PDF statements from bankstatements/, maps the columns, extracts rows and checks them against the statement's running balance, then imports transactions with the source file's hash.

3

Invoices

search-email-invoicessave-invoicesreview-invoicesextract-invoicesuser

Optionally finds bills in Gmail and saves the ones the user ticks into invoices/. Review-invoices groups duplicates and non-invoices and quarantines only approved files. Extract-invoices reads each document into invoices, lines and GST evidence.

4

Transactions

classify-transactionsmatch-paymentsallocate-running-costsuser

Proposes a treatment for every bank line, grouped by payee: account, GST, linked invoice. Nothing is posted until the user approves. Approval posts a balanced journal. Payment matches and home-office running-cost allocations follow the same propose-then-confirm rule.

5

Payroll and BAS items

grill-me-taxprepare-basuser

Sixteen period scope questions (PAYG withholding and instalments, fuel tax, vehicles, director loans and so on), each saved with evidence and provenance. PAYG withholding figures (W1 to W5) are recorded here.

6

Reconciliation

reconcile-accounts

Checks imported movements against each statement's opening and closing balance. A balance worked out from rows is marked as derived and still needs a printed figure from the bank.

7

BAS draft

prepare-basprepare-tax-report

Builds the Simpler BAS workpaper (G1, 1A, 1B, plus W labels where applicable) from reviewed entries only, with the evidence behind each figure. The annual tax report produces a trial balance and income and expense workpaper. Neither is lodged.

How progress is tracked

There is no separate checklist to keep in sync. workflow-status reads the database and lists open problems, each with a code, the owning skill, who can fix it and its step. The coordinator works the list until only user items remain.

Readworkflow-status lists open problems for the period.
PickThe first problem a worker can fix, in step order.
RunThe owning skill does the work and saves results.
StopWhen only questions and approvals are left, ask them all at once.

manage-accounting does this inside a chat. accounting_runner.py does the same from the command line, one Codex turn per problem, and scripts/simulate_user.py answers its stops from a test answers file for end-to-end tests on marked test workspaces only.

Rules the code enforces

Books

  • Money is stored in integer cents; journals must balance.
  • Nothing posts without an approved proposal.
  • Corrections are reversals, never edits; audit events are append-only.
  • Source files are hashed and copied into the workspace.
  • One business per workspace.

Tax

  • GST credits need saved tax-invoice evidence.
  • ATO citations must quote the guide word for word; the code checks the quote.
  • Unknown facts stay unknown; nothing defaults to yes.
  • BAS output is a draft workpaper; nothing is lodged.

Email

  • Codex searches Gmail through its own connector.
  • search_bills only tidies the results, on this computer.
  • Only ticked invoices are saved, with a manifest.csv.

Local pages

  • Served on 127.0.0.1 with a per-page token and origin check.
  • Buttons need network_access, which the user turns on.
  • Without it, pages open as files and copy-and-paste still works.

The ATO library

Guides in ato-library/ are added with ato-add, which extracts each page's text into library.json. Searches split pages into passages at their headings and rank them with SQLite full-text search (BM25, word stemming). Results carry the guide, page, a link that opens the PDF at that page, and warnings for stale guides or guides cited outside the period they cover.

Build, install and test

Install

  • Users add 8intcloud8/ai-accounting as a plugin source in Codex Desktop, then type “Set up my accounting”.
  • Maintainers run scripts/install.py from a checkout.

Build

  • scripts/build_release.py copies the core and library.json into each plugin and records file hashes.
  • Edit only accounting_core/; bundled copies are generated.

Test

  • python3 -m pytest: 154 tests on temporary workspaces.
  • npm test in each mcp-server/.
  • scripts/simulate_user.py for a full BAS run with Codex.

Never committed

  • Statements, invoices, spreadsheets, databases and workspace folders.
  • Real test answers stay in the private test workspace.
